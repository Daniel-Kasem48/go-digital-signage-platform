# Digital Signage Platform — Go Backend + React Dashboard

A multi-tenant **digital signage** platform: businesses register screens (devices), build layouts with zones, upload content, group it into playlists and channels, schedule what plays when, and push changes to every screen **in real time** over WebSockets.

**Stack:** Go · Echo · Uber Fx · PostgreSQL · sqlc (type-safe SQL) · goose migrations · NATS (messaging + KV state) · WebSockets · S3-compatible storage (MinIO / AWS S3) · JWT · Swagger · Docker Compose · React 18 + TypeScript + Tailwind (dashboard)

## What it does

| Area | Features |
|---|---|
| **Tenants & users** | multi-tenant data model, users, JWT access + refresh tokens |
| **Device registration** | screens pair through a challenge flow (`auth-challenge`) and get a device token; device groups |
| **Layouts & templates** | layouts split the screen into **zones**; HTML templates (samples in `sample-templates/`) |
| **Content** | images, videos, web and template content stored in S3-compatible storage |
| **Playlists** | ordered playlist items per zone with durations and validation |
| **Channels & schedules** | channels assigned to devices / groups, with time-based schedules |
| **Real-time sync** | when content or schedules change, devices are notified over **WebSockets**; **NATS** carries events and keeps device state in a KV store, so several API instances can serve the same screens |
| **Dashboard** | React + TypeScript dashboard (`frontend/`) |
| **Device simulator** | `device-simulator.html` plays the role of a screen for local testing |

## Architecture

```
React dashboard ──REST──►  Echo API (Go, Uber Fx modules)  ──sqlc──►  PostgreSQL
                                  │        │
                                  │        └──► MinIO / S3 (content files)
                                  ▼
                               NATS  (events + KV device state)
                                  │
Screens / players ◄──WebSocket────┘   (/ws?token=<device-jwt>)
```

- **One module per domain** in `internal/modules/` (device, device-registration, layout, template, content, playlist, playlist-item, channel, channel-schedule, tenant, user, file, socket, content-sync …), each with controller, service and Fx wiring.
- **sqlc**: SQL in `internal/db/queries/*.sql` → generated, type-safe Go in `internal/db/autogenerated/`.
- **goose** migrations in `schema/migrations/`.
- Tenant and device middleware (device JWT), request validation with readable per-field errors, Swagger docs generated with swag.

## Project structure

```

├── config/               # env configuration

├── modules/              # one folder per domain

```

## Getting started

Requirements: Go 1.23+, PostgreSQL, Docker (MinIO, NATS), Node 18+ for the dashboard.

```bash
cp .env.example .env                 # database, JWT secrets, storage, NATS
docker compose up -d minio nats      # object storage + messaging
./start-minio.sh                     # create the bucket
make setup                           # installs sqlc + goose into ./bin
make migrate-up                      # run migrations
go run ./cmd/digital-signage         # API on http://localhost:8080

cd frontend && cp .env.example .env && yarn && yarn dev
```

- Swagger UI: `http://localhost:8080/swagger/index.html`
- WebSocket for screens: `/ws?token=<device-jwt>`
